### 4. Правила и инварианты
1. Детальный состав сценариев, тестовых групп, шаблонов, контрольных данных, ожидаемых результатов и методов проверки согласуется с Заказчиком **до начала** ПСИ (18.3).
2. Состав сценариев — «не менее» перечней 18.1 и 18.3: сокращение не допускается, проверки сверх требований ТЗ не вводятся.
3. Ожидаемый результат описывает наблюдаемое состояние (ответ интерфейса или API, запись в базе, запись в журнале, видимость в интерфейсе); «работает корректно» недопустимо.
4. Неполный результат успешным не признаётся: частичное покрытие перечня видов данных, сценариев или типов критичных результатов не заменяет полного.
5. Реальные секреты не используются и не запрашиваются; в сценариях имитации ввода применяются заведомо недействительные значения-маркеры (7.6, 7.7, 10.1).
6. Нормативы подтверждаются по отметкам времени журналов платформы и приёмников, а не по наблюдению с рабочей станции проверяющего.
7. Параметры стенда и контрольные данные фиксируются до проверки; изменение в ходе проверки делает замер недействительным (`arch/06`, п. 1.2).
8. Решение по разночтению действительно только с отметкой согласования Заказчиком; без неё соответствующий норматив непроверяем на приёмке.

### 5. Фиксация и прослеживаемость
Каждый сценарий трассируется на пункт ТЗ и строку матрицы трассировки `arch/06` раздела 2. Приложения: реестр согласованных решений по разночтениям с датами, формы протоколов, перечень контрольных данных, перечень заменителей, журнал версий ПМИ.

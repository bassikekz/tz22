# Постановки для разработки: интерфейсы оператора и участника (CA_PS-2026-10)

Роль-исполнитель: Frontend-разработчик. Объём: `web-admin` (P22-69) и `web-portal` (P22-71).
Источники: месячное ТЗ `docs/source/tz-ca_ps-2026-10.txt`; доменная модель
`docs/arch/02-domennaya-model.md`; границы модулей и внешний API `docs/arch/01-moduli-i-granicy.md`;
роли и видимость `docs/arch/04-bezopasnost-i-privacy.md`; реестр вопросов `docs/05-otkrytye-voprosy.md`.

**Сквозное правило обоих интерфейсов (мес. ТЗ п. 4; И-11).** Полномочия проверяются на стороне
приложения (ядро, модуль M11). Интерфейс только скрывает недоступное: отсутствие кнопки или
записи в списке не является средством защиты. Каждая операция, скрытая в интерфейсе, должна
получать отказ сервера при прямом вызове API. Клиент не содержит бизнес-проверок как
единственного места контроля: он повторяет серверные ограничения только для подсказок
пользователю и всегда отображает решение сервера как окончательное.

## P22-69 — Интерфейс оператора: реестр материалов и повторное открытие опубликованной версии
**Основание:** ТЗ CA_PS-2026-10, п. 3.1 (реквизиты и публикация материала, повторное открытие
опубликованной версии, ограничение прав), п. 3.2 (понятные ошибки, неполный результат),
п. 4 (аутентификация, профиль чтения, проверка полномочий приложением)
**Модуль:** M1 (чтение статусов назначений — M2, журнал — M12) · **Компонент:** `web-admin`

### 1. Экраны и состояния

| Экран | Назначение | Кто видит | Состав данных | Состояния: загрузка / пусто / ошибка / нет прав |
|---|---|---|---|---|
| E69-1 «Реестр материалов» | список материалов с версией, владельцем, состоянием; поиск и фильтр по состоянию | методолог обучения, оператор кампаний, профиль чтения (только чтение); администратор платформы — чтение | наименование, владелец, номер текущей опубликованной версии, состояние (черновик / опубликована / не актуальна), время публикации | скелетон строк без подмены старыми данными / «Материалы не найдены» + подсказка о фильтре / баннер с текстом ошибки и кнопкой «Повторить» / экран «Доступ к реестру материалов не предоставлен» |
| E69-2 «Карточка материала» | реквизиты материала и перечень его версий | те же, что E69-1 | реквизиты материала, таблица версий (номер, состояние, автор, время публикации), признак «текущая опубликованная» | индикатор в области карточки / «У материала нет версий» / сообщение об ошибке с кодом обращения / «Материал недоступен» без раскрытия факта существования черновика |
| E69-3 «Просмотр опубликованной версии» | повторное открытие опубликованной версии в режиме только чтение | оператор и профиль чтения — чтение; поля ввода отсутствуют | содержимое версии, её реквизиты, явная плашка «Опубликованная версия, изменение недоступно» | прогресс загрузки содержимого из хранилища / «Содержимое версии отсутствует» как ошибка, не как пустой материал / «Не удалось загрузить содержимое версии» / «Версия недоступна» |
| E69-4 «Публикация версии» (диалог) | подтверждение публикации черновика | только профиль с правом публикации | номер версии, перечень обязательных реквизитов и их полнота, предупреждение о неизменяемости | кнопка в состоянии ожидания и блокировка повторного нажатия / — / текст отказа сервера дословно в понятной формулировке / диалог недоступен, кнопка не отображается |
| E69-5 «Статус прохождения по материалу» | агрегированный статус назначений по версии материала | оператор и профиль чтения в объёме полномочий | число назначенных, число завершённых, число незавершённых; персональный список — только при наличии права на персональные результаты | индикатор / «Назначений по версии нет» / «Статистика недоступна, показатели не рассчитаны» / блок скрыт полностью |

### 2. Действия и их доступность

| Действие | Кому доступно | Предусловие | Что происходит | Поведение при отказе сервера |
|---|---|---|---|---|
| Открыть реестр, карточку, список версий | все роли с правом чтения каталога | аутентифицированная сессия | `GET` соответствующего ресурса | 401 — переход на вход с сохранением адреса возврата; 403 — экран «нет прав» |
| Повторно открыть опубликованную версию | оператор, профиль чтения | версия в состоянии «опубликована» | открытие E69-3 в режиме только чтение | 404/403 — «Версия недоступна или не опубликована», без деталей о черновике |
| Опубликовать версию | профиль с правом публикации (п. 3.1) | версия — черновик, обязательные реквизиты заполнены | `POST ...:publish` с `Idempotency-Key`, затем обновление карточки | 403 — «Публикация доступна только профилю с правом публикации»; 409 — «Версия уже опубликована или изменена, карточка обновлена»; 5xx — состояние версии не меняется в интерфейсе |
| Добавить материал или версию | профиль с правом добавления | — | переход в форму (реализация формы — P22-67) | 403 — кнопка не показывается, прямой переход по адресу даёт экран «нет прав» |
| Любое изменение из профиля чтения | недоступно | — | элементы управления не отображаются | прямой вызов API отклоняется сервером (403); интерфейс показывает «Профиль чтения не изменяет данные и настройки» |
| Повторить неуспешный запрос | все | предыдущий запрос завершился ошибкой | повторная отправка; для изменяющих операций — тот же `Idempotency-Key` | повторная ошибка показывается с тем же кодом обращения, дубликат не создаётся |

### 3. Правила отображения

- Показывается: наименование, владелец, номер версии, состояние, время публикации, содержимое
  **опубликованной** версии; агрегированные показатели прохождения (п. 3.2; И-18).
- Не показывается: содержимое и реквизиты черновика пользователям без права на каталог;
  персональные результаты участников — профилю чтения, оператору кампаний и администратору
  платформы (они видят только агрегаты, `docs/arch/04-bezopasnost-i-privacy.md`, п. 1.2 и 2);
  значения введённых учётных данных и секретов — ни в интерфейсе, ни в сообщениях об ошибках
  (мес. ТЗ п. 4; И-09). Персональный список участников в E69-5 выводится только при наличии
  соответствующего права, иначе блок скрыт и запрос не отправляется.
- Профиль чтения: все элементы создания, изменения, удаления и публикации отсутствуют в вёрстке
  (а не отключены визуально); режим профиля определяется по правам из ответа сервера.
- Сообщения об ошибках (п. 3.2): формулировка на русском, без технических трасс и
  идентификаторов внутренних объектов; структура «что произошло — что сделать»; к каждому
  сообщению прилагается код обращения для журнала. Примеры: «Не удалось загрузить реестр
  материалов. Повторите попытку; при повторе сообщите код DR-0001»; «Срок сессии истёк, войдите
  повторно»; «Версия уже опубликована, данные карточки обновлены».
- Неполный результат не отображается как успешный: если список или статистика получены
  частично (часть источников недоступна), блок помечается плашкой «Данные неполные» с перечнем
  недоступных частей, итоговые значения не выводятся как окончательные, статус операции
  публикации не показывается как «выполнено» до подтверждающего ответа сервера (п. 3.2; И-04).

### 4. Взаимодействие с API

| Назначение | Эндпоинт | Примечание |
|---|---|---|
| Реестр материалов | `GET /api/materials` | пагинация, фильтр по состоянию; состав полей задаёт сервер по правам |
| Карточка и версии | `GET /api/materials/{id}`, `GET /api/materials/{id}/versions` | список версий фильтруется сервером |
| Повторное открытие версии | `GET /api/materials/{id}/versions/{version}` + ссылка на содержимое (M16) | только состояние «опубликована» |
| Публикация | `POST /api/materials/{id}/versions/{version}:publish` | обязательный заголовок `Idempotency-Key` |
| Статус прохождения | `GET /api/assignments?material_version_id=...` (M2) | агрегаты; персональный состав — по правам |

Обработка кодов: **401** — единый перехватчик, очистка состояния клиента, переход на вход,
возврат на запрошенный адрес после входа, никакие данные из кэша не показываются; **403** —
экран или блок «нет прав» с объяснением профиля, без повторных автоматических попыток;
**409** — конфликт состояния: перезапрос актуального состояния объекта и сообщение «Состояние
изменилось, карточка обновлена», действие не повторяется автоматически; **5xx и сетевая
ошибка** — сообщение с возможностью повторить, повтор изменяющих операций только с прежним
`Idempotency-Key`. Клиент не решает самостоятельно, разрешена ли публикация и видна ли версия:
доступность элементов строится по правам и состояниям из ответа сервера (мес. ТЗ п. 4).

### 5. Зависимости и блокировки

- Предшественники: P22-66 (схема данных материала), P22-67 (добавление материала и хранение
  содержимого), P22-68 (публикация и разграничение прав), P22-74 (аутентификация и профили
  доступа), P22-79 (понятные ошибки и признак неполного результата).
- Смежные: P22-70 и P22-73 — источник статусов назначений для E69-5; P22-76 — журнал операций.
- Требуют решения Заказчика: вопрос **5.4 / 4 (прил. 01)** — какая роль видит персональные
  результаты, а какая только агрегаты (без этого состав E69-5 фиксируется по минимуму — только
  агрегаты); вопрос **7.3** — контрольные данные, форматы и допустимые значения реквизитов
  (ограничения длины наименования, формат номера версии); вопрос **4.9** — минимальный размер
  агрегата при выводе показателей.

### 6. Определение готовности (DoD)

1. Экраны E69-1…E69-5 реализованы со всеми четырьмя состояниями (загрузка, пусто, ошибка, нет прав).
2. Опубликованная версия открывается повторно, элементы изменения на экране отсутствуют (п. 3.1).
3. Профиль чтения не имеет элементов изменения, прямой вызов изменяющего API отклоняется сервером — проверено совместно с P22-68 и P22-74.
4. Ни один текст интерфейса, сообщение об ошибке и журнал клиента не содержат секретов и значений учётных данных.
5. Неполный результат визуально отличим от успешного; сценарий подтверждён (п. 3.2).
6. Тест-кейсы FE-69-01…FE-69-10 выполнены на согласованном стенде; результаты приложены к P22-81.

### 8. Что не входит

Формы добавления материала и загрузки содержимого (P22-67), серверная логика публикации и прав
(P22-68), создание назначений (P22-70), панель управления и отчёты по 7.14–7.15 (P22-31),
тесты знаний, массовое обучение, внешние уведомления и кадровые интеграции (мес. ТЗ п. 5).

## P22-71 — Интерфейс участника: показ назначения, черновик не выдаётся
**Основание:** ТЗ CA_PS-2026-10, пп. 3.1, 3.2 (показ назначения участникам, фиксация
прохождения согласованным действием, недоступность черновика и результатов других),
п. 4 (участники видят только разрешённые им сведения)
**Модуль:** M2 (содержимое версии — M1/M16) · **Компонент:** `web-portal`

### 1. Экраны и состояния

| Экран | Назначение | Кто видит | Состав данных | Состояния: загрузка / пусто / ошибка / нет прав |
|---|---|---|---|---|
| E71-1 «Моё обучение» | перечень назначенных участнику материалов | работник-участник — только свои назначения | наименование материала, номер опубликованной версии, срок, статус прохождения (не начато / начато / завершено) | скелетон списка / «Назначенного обучения нет» (штатное состояние для неназначенного участника) / «Не удалось загрузить список назначений» + повтор / вход требуется |
| E71-2 «Карточка назначения» | сведения о назначении и переход к материалу | участник — владелец назначения | материал, версия, срок, статус, время завершения (если есть) | индикатор / — / понятное сообщение / «Назначение недоступно» без раскрытия чужих данных |
| E71-3 «Просмотр материала» | открытие опубликованной версии назначенного материала | участник — владелец назначения | содержимое опубликованной версии и её реквизиты | прогресс загрузки / «Содержимое недоступно» как ошибка / сообщение с кодом обращения / «Материал недоступен» |
| E71-4 «Подтверждение прохождения» | согласованное действие участника, фиксирующее прохождение | участник — владелец назначения | номер версии, явная формулировка подтверждения, кнопка подтверждения | кнопка в состоянии ожидания, повторное нажатие заблокировано / — / «Подтверждение не сохранено, повторите» / действие скрыто |
| E71-5 «Мои результаты» | собственные записи прохождения | участник — только свои | материал, версия, время фиксации, статус | индикатор / «Записей нет» / сообщение об ошибке / блок скрыт |

### 2. Действия и их доступность

| Действие | Кому доступно | Предусловие | Что происходит | Поведение при отказе сервера |
|---|---|---|---|---|
| Открыть список назначений | участник | аутентифицированная сессия | `GET /api/my/assignments` — сервер возвращает только назначения текущего пользователя | 401 — вход; 5xx — сообщение и повтор без потери места в интерфейсе |
| Открыть опубликованную версию материала | участник, которому назначена эта версия | назначение активно, версия опубликована | `GET` содержимого по идентификатору назначения | 403/404 — «Материал недоступен», одинаковая формулировка для чужого и для черновика (не раскрывает существование объекта) |
| Подтвердить прохождение | участник — владелец назначения | материал открыт, назначение не завершено | `POST ...:complete` с `Idempotency-Key`; статус меняется только после ответа сервера | 409 «уже зафиксировано» — статус синхронизируется, вторая запись не создаётся; 5xx и обрыв связи — «Подтверждение не сохранено», повтор с тем же ключом |
| Открыть материал, который не назначен (прямая ссылка) | недоступно | — | запрос отклоняется сервером | «Материал недоступен или не назначен вам» |
| Посмотреть результаты других участников | недоступно | — | элементы отсутствуют, запросов по чужим идентификаторам интерфейс не формирует | прямой вызов отклонён сервером (403) |
| Изменить или отозвать зафиксированное прохождение | недоступно | — | элементы отсутствуют (запись неизменяема, И-16) | 403/409 от сервера с понятным сообщением |

### 3. Правила отображения

- Показывается: только собственные назначения, только опубликованные версии назначенных
  материалов, только собственные записи прохождения и собственный статус (мес. ТЗ пп. 3.2, 4; И-02).
- Не показывается ни в списке, ни по прямой ссылке: черновики версий и их содержимое (И-01),
  неназначенные материалы, назначения и результаты других участников, рейтинги и персональные
  показатели иных работников, служебные сведения (владелец материала, журнал, внутренние
  идентификаторы чужих объектов). Фильтр по участнику интерфейс не передаёт — выборка
  ограничивается сервером по субъекту сессии.
- Отказ по чужому и по неопубликованному объекту даёт одинаковый текст и один код состояния,
  чтобы интерфейс не подтверждал существование черновика.
- Сообщения об ошибках (п. 3.2): «Не удалось загрузить назначенное обучение. Повторите попытку»;
  «Подтверждение прохождения не сохранено. Нажмите «Повторить» — повторная отправка не создаст
  вторую запись»; «Материал недоступен или не назначен вам»; «Срок сессии истёк, войдите повторно».
- Неполный результат не считается успешным: статус «Завершено» выставляется только по
  подтверждению сервера; при обрыве связи показывается «Статус не подтверждён» и выполняется
  перезапрос; частично загруженный материал помечается «Материал загружен не полностью, подтвердить
  прохождение нельзя» и кнопка подтверждения остаётся недоступной (п. 3.2; И-04).
- Секреты и значения введённых учётных данных не отображаются и не попадают в журналы клиента;
  личный кабинет не содержит форм ввода пароля вне процедуры аутентификации (мес. ТЗ п. 4; И-09).

### 4. Взаимодействие с API

| Назначение | Эндпоинт | Примечание |
|---|---|---|
| Список своих назначений | `GET /api/my/assignments` | область ограничена сервером по субъекту сессии |
| Карточка назначения | `GET /api/my/assignments/{id}` | чужой идентификатор — 403/404 |
| Содержимое версии | `GET /api/my/assignments/{id}/material` | только опубликованная версия |
| Подтверждение прохождения | `POST /api/my/assignments/{id}:complete` | обязательный `Idempotency-Key`, формируется один раз на попытку |
| Свои результаты | `GET /api/my/completions` | только собственные записи |

Обработка кодов: **401** — переход на вход, очистка клиентского состояния, возврат на адрес
назначения после входа; **403** — «Материал недоступен или не назначен вам», автоматические
повторы запрещены; **409** — прохождение уже зафиксировано: интерфейс забирает актуальный статус
и показывает «Прохождение уже зафиксировано», дубликат не создаётся; **5xx и обрыв связи** —
повтор с тем же `Idempotency-Key`, до подтверждения статус не считается завершённым. Проверки
«назначен ли материал», «опубликована ли версия», «не завершено ли назначение» выполняются
сервером; клиент их дублирует только для блокировки заведомо некорректного действия (мес. ТЗ п. 4).

### 5. Зависимости и блокировки

- Предшественники: P22-70 (программное назначение группе), P22-72 (фиксация прохождения:
  материал, версия, участник, время), P22-73 (статус прохождения и норматив 5 минут),
  P22-74 (аутентификация участника), P22-68 (публикация версии), P22-79 (ошибки и признак неполноты).
- Требуют решения Заказчика: вопрос **1.6** — способ аутентификации работника в личном кабинете
  (корпоративный SSO либо локальные учётные записи; для месячного объёма используются локальные,
  мес. ТЗ п. 5); вопрос **7.3** — согласованные контрольные данные, состав локальной тестовой
  группы и формулировка «согласованного действия» подтверждения прохождения; вопрос **6.1** —
  точка t0 норматива 5 минут, влияет на подсказку участнику о появлении назначения;
  вопрос **5.2** — порядок предоставления персональных результатов (состав E71-5).

### 6. Определение готовности (DoD)

1. Экраны E71-1…E71-5 реализованы со всеми состояниями; неназначенный участник видит пустой список без ошибок.
2. Черновик недоступен ни в списке, ни по прямой ссылке; формулировка отказа не раскрывает существование объекта (пп. 3.1, 3.2).
3. Результаты и назначения других участников недоступны; интерфейс не формирует запросов по чужим идентификаторам (п. 4).
4. Повторное подтверждение прохождения, в том числе после обрыва связи, не создаёт вторую запись (проверено с P22-72).
5. Неполная загрузка материала и неподтверждённый статус визуально отличны от успешного завершения (п. 3.2).
6. Тест-кейсы FE-71-01…FE-71-10 выполнены на стенде; результаты приложены к P22-81.

### 8. Что не входит

Серверное создание назначений и контроль норматива 5 минут (P22-70, P22-73), серверная фиксация
прохождения (P22-72), тесты знаний (7.4), рейтинги и персональные показатели (7.10–7.13),
кнопка «Сообщить о письме» и личный кабинет полного объёма (P22-32), внешние уведомления
и напоминания, массовое обучение и кадровые интеграции (мес. ТЗ п. 5).
